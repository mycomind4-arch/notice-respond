# Vertical Audit Skill

Use before building any MailMyPDF vertical.

1. Inspect the target repository and the MailMyPDF Platform.
2. Build a reuse matrix for identity, entitlement, documents, extraction, AI, evidence, timelines, workflows, proof, fulfillment, security and UI.
3. Inspect the most mature existing verticals for reusable patterns; do not copy vertical-specific rules.
4. Classify every planned capability as REUSE, EXTEND PLATFORM, or VERTICAL.
5. Refuse duplicate identity, billing, evidence, document or proof infrastructure unless the platform is genuinely missing a reusable primitive.
6. Establish provenance, confidence and verification rules before AI work begins.
7. Produce a minimal MVP scope before implementation.

Exit criteria: a repository-specific build map, explicit platform boundary, threat model, test strategy and MVP acceptance criteria.
