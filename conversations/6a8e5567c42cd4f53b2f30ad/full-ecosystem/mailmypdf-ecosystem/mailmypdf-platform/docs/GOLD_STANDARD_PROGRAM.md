# MailMyPDF Gold-Standard Workflow Program

## Objective
Bring every customer-facing workflow in every MailMyPDF vertical to the same executable quality bar as the strongest Notice Respond workflow.

## Canonical pipeline
1. Secure ingest
2. Classification
3. Structured extraction
4. Understanding / case model
5. Provenance and source traceability
6. Timeline and deadline intelligence
7. Issue / discrepancy detection
8. Evidence organization and sufficiency
9. Authority / research where domain-appropriate
10. Risk / strength assessment
11. Response strategy
12. Grounded drafting
13. Draft and requirement validation
14. Blocking quality gates
15. Human review
16. Real MailMyPDF fulfillment
17. Tracking
18. Proof / audit preservation

## Non-negotiable rules
- A catalog entry is not an executable workflow.
- A workflow is executable only when its declared capabilities are implemented and registry validation passes.
- No fabricated analysis, evidence, deadlines, mailing, tracking, or proof.
- Findings and drafted claims must be traceable to source material or explicitly identified authority.
- Reuse shared platform capabilities instead of duplicating engines.
- Domain-specific adapters own domain reasoning; the platform owns reusable infrastructure.
- Existing working workflows must be upgraded without regressing behavior.
- Gold-standard status requires focused tests plus full regression.

## Ten-milestone program

### Milestone 1 — Contract and inventory
Create the canonical parity contract and inventory every repo/workflow/capability state.

### Milestone 2 — Reference implementation
Measure Notice Respond against the contract and close any remaining reference gaps.

### Milestone 3 — Shared execution primitives
Ensure Documents, Evidence, Contradictions, Timeline, Deadline, Risk, Case Analysis, Validation, Security, Audit, Fulfillment, Tracking and Proof expose reusable contracts.

### Milestone 4 — Appeal Mail
Bring Insurance Appeal through the complete executable pipeline and make its other catalog workflows use honest executable/catalog separation.

### Milestone 5 — Dispute Mail
Bring every existing dispute workflow through the same pipeline using dispute-specific issue/evidence/strategy adapters.

### Milestone 6 — Immigration Mail
Bring every existing immigration workflow through the pipeline with immigration-specific document/request analysis, evidence organization, strategy, drafting and validation.

### Milestone 7 — Small Business
Bring every existing business correspondence workflow through the pipeline, including scheduling/approval/fulfillment boundaries that are actually implemented.

### Milestone 8 — Government and administrative verticals
Upgrade GovReply, Code Enforcement, Records Requests, Permit Response, Tenant Reply and related workflows using the shared contract.

### Milestone 9 — Claims, benefits and debt verticals
Upgrade Insurance Claims, Benefits Appeal, Debt Defense, Case Evidence and remaining related workflows.

### Milestone 10 — Ecosystem certification
Run cross-repo parity tests, production builds, security checks, deployment smoke tests and produce a workflow certification matrix. No workflow receives Gold Standard status without evidence.

## Certification levels
- CATALOG: discoverable product page only.
- PARTIAL: executable pieces exist but the full pipeline is incomplete.
- EXECUTABLE: complete real pipeline, but parity evidence is still being finalized.
- GOLD: complete pipeline, domain-specific reasoning, traceability, validation gates, fulfillment boundary, regression coverage and deployed smoke-test evidence.

## Required final artifact
`docs/GOLD_STANDARD_CERTIFICATION.md` must list every workflow, repository, certification level, missing capabilities, tests, build status, deployment status and exact next action.
