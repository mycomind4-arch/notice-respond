# MailMyPDF Gold-Standard Execution Program

## Objective
Bring every workflow in every MailMyPDF vertical repository to genuine executable Gold Standard. Visual polish alone never qualifies.

## Canonical pipeline
Secure ingest -> classify -> extract -> understand -> normalize facts/provenance -> timeline/deadlines -> issues/discrepancies -> evidence -> authority/research where required -> strength/risk -> strategy -> draft -> validate -> blocking gates -> human review -> authorized mail -> track -> prove/audit.

## Status model
- CATALOG: customer-facing discovery only; no executable claims.
- PARTIAL: real functionality exists but one or more required stages remain incomplete.
- EXECUTABLE: real end-to-end path exists but parity certification is incomplete.
- GOLD: all applicable stages are implemented, integrated, tested, security-gated, and verified in the deployed path.

## Ten milestones
1. Contract + complete workflow inventory
2. Notice Respond reference certification
3. Shared execution primitives
4. Domain-pack SDK and adapter contracts
5. Appeal Mail gold-standard workflows
6. Dispute Mail gold-standard workflows
7. Immigration Mail gold-standard workflows
8. Small Business + government/administrative workflows
9. Claims, benefits, debt, tenant, permit, records and remaining workflows
10. Ecosystem-wide certification and deployed smoke tests

## Rules
1. All changes go directly to `main` unless explicitly authorized otherwise.
2. Never use subagents.
3. Never fake tests, builds, deployment, mailing, tracking, proof, AI findings, or integrations.
4. Reuse shared platform capabilities instead of duplicating engines.
5. Domain adapters must supply domain-specific classification, rules, findings, strategy, and drafting requirements.
6. Every executable workflow must have representative fixtures and regression tests.
7. A catalog page must never imply executable capability that the registry does not actually provide.
8. A consequential action must pass validation, authorization, and human-review gates.
9. Unknown and missing evidence remain explicit states.
10. After each meaningful milestone: test, build where applicable, inspect diff, commit to `main`, push to `main`, and update state documentation.

## Certification
A workflow is Gold only when the actual deployed path demonstrates the required pipeline, traceability, validation, security, fulfillment, tracking, proof, and regression behavior. Notice Respond is the reference for depth, not a source for blindly copied domain logic.
