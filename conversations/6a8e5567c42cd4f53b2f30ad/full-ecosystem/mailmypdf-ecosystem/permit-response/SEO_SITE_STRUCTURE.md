# Permit Reply — Canonical SEO Site Structure

Preserve ecosystem-wide navigation. This defines the SEO/content hierarchy and must not remove working routes.

## Public
- `/` — Permit Reply pillar: respond to permit corrections, requests and agency comments; correspondence types; how it works; what to gather; AI handles heavy lifting; review; mailing/proof; featured workflows; FAQ; start.
- `/workflows` — Permit Reply workflow hub with situation discovery, search, category navigation and crawlable authority pages.
- `/how-it-works` — upload permit notice/comments → AI understands agency request → organize facts/supporting documents → build response → review/approve → MailMyPDF sends → track/preserve proof.
- `/products`, `/pricing`, `/mail-a-pdf` — ecosystem/product pages.
- `/about`, `/contact`, `/faq`, `/resources/*` — supporting SEO/footer content.
- `/privacy`, `/terms`, `/404` — legal/error.

## Workflow taxonomy
Permit corrections; building permits; planning & zoning; development & construction; specialty permits; agency follow-up; general permit responses.

## SEO flow
Pillar → workflow hub → specific authority page → authenticated reply workflow. Preserve existing workflow URLs and use problem/search intent as the page organizing principle.

## Simplicity rule
AI handles permit-document and plan/drawing analysis, comment extraction, requirement identification, facts, deadlines, evidence organization, issue-by-issue response planning, drafting, attachment/recipient validation and mailing preparation.

## Navigation lock
No vertical-specific navigation additions. Use the existing ecosystem shell.
